# Mobile map loading

The nationwide index uses a lossless column encoding in static releases. Numeric deltas, repeated values and dictionaries reduce compressed transfer from 3,595,394 to 1,985,259 bytes. A separate `compact-index` asset keeps the original index compatible with older open tabs. The data worker restores the original scoring inputs before evaluation; a full round-trip test checks every cell. Source datasets and detailed scoring are unchanged. Worker-less browsers use the same decoder. The source script-envelope preview format remains supported.

At zoom 10 and below, forest coverage uses categorical raster masks built from the existing 100 m simplified forest outlines. These encode forest IDs, not baked species colors or probabilities. The browser colors them using the currently selected species, weather and viewport scale. Clicks resolve to the same forest IDs. The complete 31-chunk set drops from 8,869,312 to 1,347,743 compressed bytes. The roughly 100 m display pixels are a low-zoom representation, not new measurements. Zoom 11+ keeps the vector footprints; zoom 13+ retains the 50 m local data. Both worker and canvas fallbacks support the masks, with bounded painted-mask caches.

Rebuild coverage with `python scripts/build_mobile_overview.py` after changing overview sources. Pillow is in `scripts/requirements.txt`; the main forest-overview build invokes this step too. `build:static` creates the compact index automatically. No new browser library or production server is required.

The initial manifests, basemap metadata and index download concurrently. Startup includes bundled weather before the first score batch, avoiding an immediate second national evaluation. The 1.35 MB offline SVG loads only when offline mode is selected or online tiles fail. Reserve boundaries start after the first overview paint or after three seconds; the existing pending/unavailable protection status remains visible. Very slow dataset transfers have a 90-second network limit rather than failing after 30 seconds.

A single cold comparison at 200 KiB/s app bandwidth, 100 ms response delay and a 390×844 viewport reduced recorded interactive time from 24.6 to 16.9 seconds. The overview-ready delay relative to the last scoring request dropped from 54.0 to 10.3 seconds. See `benchmarks/mobile-loading-20261102.json` for raw samples and payload sizes. The browser ran on a desktop without CPU throttling; third-party basemap tiles were not bandwidth-limited. These are controlled comparison results, not real-phone or field performance guarantees. Poor connections can still take seconds to transfer the national score index; a future viewport-scoped score index could reduce that initial floor further.

Wheel zoom now scales the existing map pane during the gesture and commits a fractional zoom after 180 ms of idle time. Tile requests, LOD selection and local-cell work run on the committed view, rather than on each wheel event. Pinch zoom and the zoom buttons keep Leaflet’s native controls. Browser magnification gestures are left to the browser.

Overview recolouring keeps one temporary painted canvas buffer until its replacement loads. Transitions between overview and fine cells retain the previous overlay until the replacement is ready; buffers are released on completion or layer removal. This affects presentation only, not habitat scores.
